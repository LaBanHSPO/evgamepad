TECHNICAL DECISIONS & RATIONALE
================================================================================

1. THREE-TIER CACHING STRATEGY
   Rationale: Eliminates single point of failure
   - Redis: Ultra-low latency for normal operations
   - MatView: Handles Redis failures gracefully
   - Direct: Guarantees freshness when needed

2. MATERIALIZED VIEW WITH CONCURRENT REFRESH
   Rationale: Non-blocking view refresh during reads
   - No SELECT locks during refresh
   - Balances freshness (30s) with DB load
   - Cost-effective for read-heavy workload

3. SORTED SETS OVER OTHER REDIS STRUCTURES
   Rationale: Optimal for ranking operations
   - O(log n) operations vs O(n) for list sorting
   - Native rank retrieval via ZREVRANK
   - Atomic ZADD prevents race conditions

4. SESSION-SCOPED LEADERBOARDS
   Rationale: Data isolation and concurrent game support
   - Prevents cross-session data leaks
   - Allows concurrent games without interference
   - Per-session TTL management
   - Simplifies cleanup on session end

5. BACKGROUND REFRESH TASK
   Rationale: Decoupled from request path
   - Non-blocking materialized view refresh
   - Recovers from DB failures automatically
   - Configurable interval for tuning
